Python SDK

Generate, export and run tests for Amazon Connect contact flows, from Python. It is the testing counterpart to cxblueprint: build or export a flow, then let Diteko derive its grammar, generate test calls that aim to cover its outcomes (with Grammatical Evolution), export them, and run them on Connect’s native testing.

This package is a client: it needs a Diteko server. It does nothing on its own. Point it at your team’s Diteko, or start one on this machine with diteko server up (it needs Docker; see https://github.com/Lehlohonolo-Sehako/diteko-selfhost).

The SDK talks to a running Diteko deployment over its REST API. If that deployment requires API keys, set DITEKO_API_KEY (or pass api_key=); otherwise point the SDK only at a deployment inside your network or behind your VPN.

Getting started

Section titled “Getting started”

  1. Find your Diteko. Diteko is self-hosted: you need the address of a running deployment. If you run your own (diteko-selfhost), that is http://localhost:8080, which is also the SDK’s default. To start one on this machine (with Docker installed):

    It needs only Docker (Docker Desktop on macOS and Windows): the self-hosting files travel in this package, and the first start downloads the server image. The first time, it creates a WRITE key and prints the two settings to export (PowerShell syntax on Windows), plus the bootstrap ADMIN key for the console at the same address. diteko server status and diteko server down do what they say; data is kept between runs, and upgrading this package upgrades the server’s files on the next up without touching your settings. --port picks another port, --latest uses the newest diteko-selfhost release instead of the files in this package, and --bundle path a self-hosting folder you already have.

Presets

Section titled “Presets”
preset calls × generations
quick 40 × 15
standard 100 × 50
thorough 200 × 120
focus favours
balanced blocks and branches, plus happy paths and recoveries
coverage visiting as much of the flow as possible
errors timeouts and wrong keys that still end properly
transfers calls that reach an agent queue

Pass population=, generations=, weights={"state_coverage": 1.0} or seed= to go beyond them.

API keys

Section titled “API keys”

A key carries one scope: READ (see and export), WRITE (also create, run and dry-run), PUBLISH_LIVE (also run on Connect for real, which is billed) or ADMIN (also manage keys). Keys are created in the console under Settings, API keys.

MCP server

Section titled “MCP server”
Tool Does
list_projects every flow under test and its next step
import_flow register a flow from JSON text, a file path, or a Connect flow id
generate_grammar derive, store and validate a flow’s grammar
convert_grammar BNF ⇄ JSON
start_evolution start a run (size, focus, seed)
get_run a run’s progress
export_suite xlsx, json or native to a file
publish_suite start a run on Connect and return at once; dry_run defaults to true, since a live run bills the AWS account
get_execution a Connect run’s status and verdicts; poll it until the status is no longer RUNNING

Each tool carries MCP annotations: read-only tools say so, and publish_suite is marked as reaching an external system. Works with mcp 1.x and 2.x.

Versioning

Section titled “Versioning”

The package follows Semantic Versioning. See the release notes for what each release changed.

The server reports an API version, MAJOR.MINOR, at GET /api/version. A minor bump only adds endpoints or fields. A major bump changes something an existing client relies on. Each SDK release speaks one API major version, currently 1. On its first call the SDK checks the server’s version:

Server What happens
API 1.x Works.
Another major DitekoError, saying whether to upgrade the SDK or the server
Too old to report a version A warning, then it carries on
Not a Diteko server DitekoError: check DITEKO_URL
Nothing answering DitekoError saying a server is needed and how to point at one; the next call checks again

Diteko(url, check_version=False) skips the check, and dk.version() returns what the server reports.
